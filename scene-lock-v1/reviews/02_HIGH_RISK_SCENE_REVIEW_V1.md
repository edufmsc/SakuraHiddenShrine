## 01｜`love.evidence` 第一項證據

**故事目的**：最近三次「下一次」究竟是誰提出，而且誰真的讓它發生。這幕第一次把曖昧從感覺拉回現實證據。

**V58 目前主圖**：
- 桌機：`LOVE_lips_hush_v44.webp`
- 手機：`love_021.webp`

**已確認現有候選存在**：
- `LOVE_VERIFY_01_next_time_proof_desktop.webp`
- `LOVE_VERIFY_01_next_time_proof_mobile.webp`

**問題判定**：目前主圖名稱與 scene gallery title 都偏「噤聲／近唇」，而故事需要日期、邀約、安排、下一次是否真正發生的證據語意。即使近身圖很漂亮，也不應繼續當主圖。

**桌機安全區**：`S-EVIDENCE`；證據物至少保留畫面約 25–35%，文字放證據相反側。

**手機安全區**：中段保留日期／安排／證據物；下方 UI 不得把證據全部蓋掉。

**最終方向**：`🔄 SWAP`。第一順位直接改驗 `LOVE_VERIFY_01_next_time_proof_desktop/mobile`；只有實機看過後仍缺「具體下一次證據」才升級 `🎨 GENERATE`。

**鎖定**：⬜

## 02｜`career.borrowed` 成果借名

**故事目的**：成果還在，但落地時被換成別人的名字。這是業卷最核心的「證據幕」。

**V58 實際故事方向**：`career.borrowed` 的情節是棋子落地後刻上別人的姓；Production 與 visual-audit 都要求「成果物＋他人姓名／印章＋九尾把證據推向玩家」。

**現有資產情況**：
- visual-audit 有 `career_borrowed_evidence.webp` 候選。
- story.js 現行另有 `career_name_swap` 對應資產邏輯。
- 業卷 active 內也已有 `CAREER_VERIFY_01_achievement_proof_desktop/mobile` 等證據型素材，可作為參考素材，不代表可直接取代此幕。

**必要畫面**：
1. 真正可辨識的成果物／文件／成果牌。
2. 另一人的姓名牌、印章或署名壓在成果上。
3. 九尾坐策略桌另一側。
4. 她用兩指把證據推向玩家。
5. 棋盤／黑棋可作輔助，但不能搶掉「借名」證據。

**桌機安全區**：`S-EVIDENCE`；證據區至少 25–35%，九尾位於另一側。

**手機安全區**：一定要同時保留「九尾手＋成果＋他人署名」三個核心。

**最終方向**：`🎨 GENERATE` 高優先。只有後續實機確認 `career_borrowed_evidence.webp` 已完整做到以上五項，才可降級為 `✅ USE/🟡 ADJUST`；不能因為已有檔名就直接視為合格。

**鎖定**：⬜

## 03｜`life.turn` 鏡外人

**故事目的**：鏡中那個永遠能撐、永遠會答應的版本其實才是替身；鏡外真正的自己反而開始透明。

**V58 目前主圖**：
- 桌機：`life_mirror_double_face.webp`
- 手機：`life_mirror_mismatch.webp`

**問題判定**：一般「雙臉／雙重倒影」不足以演出這個反轉。玩家必須一眼看懂：鏡內完整、鏡外透明，而且九尾正在揭露／拼鏡。

**必要畫面**：
1. 大鏡面或裂鏡。
2. 鏡內人物完整、穩定。
3. 鏡外人物身體／手透明化。
4. 九尾在旁拼鏡／揭露。
5. 鏡內外身份差異不用文字也能懂。

**桌機安全區**：`S-EVIDENCE`；鏡內、鏡外兩邊都不能被文字蓋掉。

**手機安全區**：直式仍需同時看到鏡內完整與鏡外透明，不可因裁切只剩一個人。

**最終方向**：`🎨 GENERATE` 高優先，除非實機像素驗收證明 `life_mirror_double_face.webp` 已完整做到「鏡內完整／鏡外透明」而不是只有美術雙臉效果。

**鎖定**：⬜

## 04｜`forbidden.turn` 面具認主

**故事目的**：狐面從九尾手中滑落，沿紅線停到玩家面前；面具內側是玩家自己的痕跡。九尾第一次站遠，不再用靠近影響答案。

**V58 目前主圖**：
- 桌機：`FORBIDDEN_dark_gaze_v44.webp`
- 手機：`forbidden_013.webp`

**問題判定**：「暗黑凝視」本身無法承擔「道具認主」這個具體動作。此幕主角其實是前景狐面與紅線，不是九尾的臉。

**必要畫面**：
1. 狐面懸在玩家前景。
2. 面具內側有刻痕／字跡感，但不可生成可讀中文字。
3. 紅線明確把面具帶向玩家。
4. 九尾退到中遠景。
5. 氣氛是反轉與承擔，不是普通威脅肖像。

**桌機安全區**：`S-EVIDENCE` 或中構圖短句；面具與紅線不能被文字遮。

**手機安全區**：狐面置中前景、九尾遠景，仍看得出距離改變。

**最終方向**：`🎨 GENERATE` 高優先；現圖可保留到其他適合的暗黑凝視幕，不應硬留在「面具認主」。

**鎖定**：⬜

## 05｜`finale.confession` 九尾失言

**故事目的**：九尾第一次真正坦白。她承認一開始確實利用四卷鬆自己的封印，也承認真正害怕的是門開後玩家不再回來。

**V58 目前主圖**：
- 桌機：`SHARED_recline.webp`
- 手機：`SHARED_fullbody_mobile.webp`

**問題判定**：shared 躺姿／全身圖可以性感，卻不一定能演出「牽玩家手貼上封印＋九尾脆弱失言」這種高度具體動作。第五卷高潮不應再用泛用 shared 圖硬撐。

**必要畫面**：
1. 九尾不再帶平常自信笑容。
2. 她牽玩家的手貼在胸前／身前封印。
3. 力道停在玩家隨時可以抽回的位置。
4. 第五印／封印前兆可見。
5. 成熟、近身、私密，但情緒核心是脆弱坦白，不是誘惑。

**桌機安全區**：`S-CLOSE`；只留短段台詞，臉、手、封印不可被 UI 壓住。

**手機安全區**：臉＋玩家手＋封印三者必須同時存在。

**最終方向**：`🎨 GENERATE` 高優先。shared 圖可留做其他過場，不作正式坦白主圖。

**鎖定**：⬜

## 06｜`finale.ending` 真結・總命牒

**故事目的**：九尾最後回來，親手展開整夜唯一的總命牒。這是整站視覺與文字最高優先頁。

**V58 目前圖片**：
- 桌機：`final_scroll_desktop.webp`
- 手機：`FINAL_SCROLL_portrait.webp`

**已知結構性問題**：現有桌機圖九尾位於畫面中央，而正式總命牒左側需要約 38–43vw 的大紙面區，兩者必然互相遮擋。這不是單純調 `object-position` 就能完全解決的問題。

**正式桌機構圖**：
- 左側約 4–42% 完整白／米白命牒安全區。
- 九尾主要位於右側約 52–85%。
- 九尾正在展卷／提筆，而不是站在紙後面。
- 頭、狐耳、眼、唇、脖、胸、手、尾巴不可被命牒蓋住。
- 背景是終局命館，不是一般人物照。

**正式手機構圖**：9:16 獨立生成；九尾與命牒上下／斜向分區，不能從桌機圖直接裁。

**程式必修**：
- 命牒標題固定。
- 內文可捲。
- 捲軸明顯可見。
- 逐字寫入時自動跟隨最新內容。
- 點命牒只能加速逐字，不直接跳下一頁。

**最終方向**：`🎨 GENERATE + 🔧 BUILD`，而且是目前全站最高優先之一。

**鎖定**：⬜
